# Pure tick

## Goal

The decisions of a tick run in an engine-free **core** that native tests reach.
The engine gathers **facts**, calls the core once per tick, and carries out the
**commands** the core returns. In-game runs check rendering, the game's
behaviour and performance. They do not check orchestration logic.

## How the area works today

`Manager::OnFrame` drives the timers, drains finished plan jobs and calls
`Manager::Tick` once per tick interval. `Tick` swaps and starts resizes, then
loops over `live_`. For each actor it ticks signals, reads sight, runs the
hidden release and the level step, renders in view, and updates lights and
applications. It then draws hidden stacks in pacing order. The metrics
heartbeat samples video memory once per second and runs the budget.

The decisions are pure planners: `NextLevelStep`, `RespondToPressure`,
`NextResize`, `HiddenDrawOrder`, `NextInstall`, `ShrinkRadius`, `GrowRadius`,
`Actors::PlanActor` and `Actors::Advance`. The engine calls them one actor and
one mechanism at a time inside loops, mixed with game calls. The order of those
calls is a rule that no test reads.

Every leak fixed on 2026-10-08 and 2026-10-09 came from two mechanisms that
meet in that layer. No fix needed the GPU to show the fault.

## The core

The core is a pure function per tick.

```
TickResult Tick(World world, TickFacts facts)  ->  { World next, Commands, TraceRecords }
```

| Type | Holds |
|---|---|
| `World` | One `ActorRecord` per actor id, the `BudgetState`, the budget radius, the waiting installs, the timer starts, the frame number. |
| `ActorRecord` | The role, the last sighting, the render phase (`planners/ActorPhase.h` with progress facts in place of resources), the level costs, the instance costs, the first rendered frame. |
| `TickFacts` | The time, the frame, the settings. Per actor: the sighting. The results of the last tick's commands. Finished plan jobs. Stale marks. A memory sample when one is due. |
| `Command` | `StartResize`, `SwapResize`, `AbandonResize`, `ReleaseIntermediates`, `RenderActor`, `DrawHidden`, `FinishApplications`, `Install`, `Retire`, `Forget`, `MarkStale`. |
| `TraceRecord` | One trace event. The engine emits it and does not write its wording. |

Rules:

- One pass per tick. The result of a fallible command is a fact of the next tick (R-1).
- The order of the command list is the order of the tick: swaps, then releases, then renders, then hidden draws.
- The engine owns every resource by actor id. Only a command creates or destroys a resource. The engine checks once per tick that each actor's resources agree with its phase (R-2).
- An install is a program of pure stages that the engine runs inside one tick (R7).

## The engine after the rewrite

The engine keeps observation (3D, worn pieces, sight, video memory), rendering
(signals, slot writes, shells, lights, GPU draws), the plan worker, and the
executors of the commands. `Manager::Tick`'s loop, the budget functions,
`ActorBudget.cpp`'s decisions, the resize scheduling and the sync decision move
into the core.

## Native tests

- Unit tests per rule.
- A simulator shell that executes commands with counters, configurable draw speed and failure injection: a resize that does not start, a failed plan job, a swap mismatch.
- Scenarios over hundreds of ticks: a crowd arriving at once, an actor that leaves the view during a resize, budget pressure during a burst of first draws, a failed resize, a failed plan job, the radius shrinking and growing.
- Invariants after every tick: no release outside `Live`; an out-of-view swap releases one hold later; at most one resize in flight; the estimate equals the sum of the held costs; a failed level is not asked for again while it stays wanted; each command agrees with its actor's phase.

## Decisions

| Id | Decision |
|---|---|
| R-1 | One pass per tick. A fallible command's result is a fact of the next tick. |
| R-2 | The engine owns resources by actor id, with a per-tick agreement check. The core is not templated over resources. This replaces S3-1 of the ownership plan. |
| R-3 | The core owns the render lifecycle, the budget, install pacing and the sync decision. The engine owns observation and the install and retire executors. |
| R-4 | The core returns trace records. The engine emits them. |
| R-5 | `planners/OutputState.*` and `planners/ActorPhase.h` from ownership stage 3 are building blocks of the core. Stage 3's engine adoption is dropped; it is in `git stash` on `main`. |
