# Pure tick

## Goal

The decisions of a tick run in an engine-free **core** that native tests reach.
The engine gathers **facts**, calls the core once per tick, and carries out the
**commands** the core returns. In-game runs check rendering, the game's
behaviour and performance. They do not check orchestration logic.

## How the area works today

`Manager::OnFrame` drives the timers, drains finished plan jobs and calls
`Manager::Tick` once per tick interval. `Tick` swaps and starts resizes, then
loops over `live_`. For each actor it ticks signals, reads sight, runs the
hidden release and the level step, renders in view, and updates lights and
applications. It then draws hidden stacks in pacing order. The metrics
heartbeat samples video memory once per second and runs the budget.

The decisions are pure planners: `NextLevelStep`, `RespondToPressure`,
`NextResize`, `UnpublishedDrawOrder`, `NextInstall`, `ShrinkRadius`, `GrowRadius`,
`Actors::PlanActor` and `Actors::Advance`. The engine calls them one actor and
one mechanism at a time inside loops, mixed with game calls. The order of those
calls is a rule that no test reads.

Every leak fixed on 2026-10-08 and 2026-10-09 came from two mechanisms that
meet in that layer. No fix needed the GPU to show the fault.

## The core

The core is a pure function per tick.

```
TickOutput Tick(World world, TickFacts facts)  ->  { World next, Commands, TraceRecords }
```

| Type | Holds |
|---|---|
| `World` | One `ActorRecord` per actor id, the `BudgetState`, the budget radius, the waiting installs, the sync log, the recheck timers. |
| `ActorRecord` | The role, the last sighting, the sync state, the reinstall level, the return bytes, and the `InstalledRender`: the render phase (`orchestration/RenderPhase.h`), the level costs, whether the install has a render, and the first rendered frame. |
| `TickFacts` | The time, the frame, the settings. Per actor: the sighting, parsed at the boundary. The results of the last tick's commands. Finished plan jobs. Each stale actor with its observed facts and its plan. A memory sample when one is due. |
| `Command` | `TickActor`, `StartResize`, `SwapResize`, `AbandonResize`, `ReleaseIntermediates`, `SetAppliedLevel`, `DrawUnpublished`, `BuildAwaitedRender`, `FailAwaitedRender`, `Install`, `Retire`, `Forget`, `Observe`, `KeepModels`, `SettleApplications`. |
| `TraceRecord`, `LogRecord` | One trace event or one log line. The engine emits them and does not write their wording. |

Rules:

- One pass per tick. The result of a fallible command is a fact of the next tick (R-1).
- The order of the command list is the order of the steps, and within the lifecycle step the unpublished draws come last. No actor gets a release and a swap in the same tick: only `Live` releases, a swap applies to `Resizing`, and its result arrives the next tick.
- The engine owns every resource by actor id. Only a command creates or destroys a resource. The engine checks once per tick that each actor's resources agree with its phase (R-2).
- An install is a program of pure stages that the engine runs inside one tick (R7).

## The engine after the rewrite

The engine keeps observation (3D, worn pieces, sight, video memory), rendering
(signals, slot writes, shells, lights, GPU draws), the plan worker, and the
executors of the commands. `Manager::Tick`'s loop, the budget functions,
`ActorBudget.cpp`'s decisions, the resize scheduling and the sync decision move
into the core.

## R0 contract

`src/orchestration/World.h`, `Facts.h`, `Commands.h` and `Tick.h` hold the
types. A wave 2 stream does not change them. A stream that needs a change asks
the main session, which changes the header for every stream.

### The boundary rule

The core owns every decision that reads or writes state shared across actors
or mechanisms, and the order of those decisions. A decision may stay at the
engine boundary only when all three hold:

- It is a pure function with its own native tests.
- It reads one actor's observation, the settings, a core command, or immutable shared input (the recipe catalog, the studio view), and nothing else.
- Its outcome reaches the core as a fact or a result.

An engine executor branches only on whether an engine call succeeded.

| Boundary function | Turns | Into |
|---|---|---|
| `InViewOf`, extracted in R4 from today's `ShownThisTick` | Camera view, `CullOutOfView`, the player, the inspected actor | `Sighting::inView` |
| `ScreenFractionOf`, extracted in R4 from today's `SizingFraction` | Screen fraction, `ScreenResolution`, the regression override | `Sighting::screenFraction` |
| `Actors::PlanActor` | Observed facts, the recipe catalog, the studio view | `StaleActor::planned` |
| `ChooseInstallLevel` | The plan's level costs and the command's `InstallBound` | `Installed::level` and `chargedBytes` |
| Unpublished-draw pacing (`MayDrawStack`, `Drew`) | Measured draw time against `DrawUnpublished::budgetUs` | `UnpublishedDrawn::drawn` |

R4 moves `InViewOf` and `ScreenFractionOf` into `planners/` with tests. `Sighting::screenFraction` is the parsed value: the raw fraction, or none when `ScreenResolution` is off.

### The render phase

`orchestration/RenderPhase.h` holds one actor's render phase: `Live`,
`WithoutRender`, `AwaitingPlan`, `FirstDrawing` or `Resizing`
(`ResizeQueued` or `ResizeRunning`). `WithoutRender` is an install that built
no render, or a plan that failed: it has no level and takes no decision. It
differs from an `ActorRecord` without `render`, which is an actor with nothing
installed. `Intermediates` is `IntermediatesHeld{outOfView}` or
`IntermediatesReleased`. `Resizing` keeps only the attached render's
`IntermediateHolding`: a resize that ends in `Live` starts a fresh
out-of-view hold, and an actor in view during a resize holds again, because
the attached render restores its intermediates when it draws. A first draw and a running resize each hold an
`UnpublishedDraw{total, drawn, beganFrame, drawTicks}`: the draw of a render
before it is published. A first draw counts slots and a resize counts stacks,
so the fields say `total` and not `stacks`.

`orchestration/PhaseChanges.h` changes a phase in two ways. Both return a
`PhaseChange`: the next phase and the commands it implies (`SetAppliedLevel`,
`ReleaseIntermediates`, `AbandonResize`).

- `PhaseFor` creates a phase from the first event of an install: `PlanAwaited`, `Installed` or `InstalledWithoutRender`.
- `OnEvent` applies a `RenderEvent`, a thing the engine reports: `PlanAwaited`, `Installed`, `InstalledWithoutRender` (accepted only in `AwaitingPlan`), `UnpublishedDrawn`, `ResizeStarted`, `ResizeNotStarted`, `ResizeSwapped`, `ResizeNotSwapped`. An event the phase cannot take leaves the phase unchanged and sets `PhaseChange::ignored`; the lifecycle step writes the trace event `actor_phase_ignored` for it.
- A resize that does not start or does not swap returns to `Live` at its old level with `FailedLevel{level, wantedThen}`, the wanted level at the time. `WantLevel` refuses that level, and `SeeActor` clears it once the wanted level differs from `wantedThen`. The budget offers no step-down to a failed level.
- A decision is a function the core calls: `FailPlan`, `WantLevel`, `ReleaseForBudget`, `SeeActor`, `EndFirstDraw`.

### Steps

`Tick` runs the steps in this order. Each step takes the `World` and the
facts and returns a `TickOutput`: the next world, its commands and its trace
records. `Tick` appends the commands in step order.

| Order | Step | Stream | File | Reads | Writes |
|---|---|---|---|---|---|
| 1 | `RecordSyncResults` | R5 | `orchestration/Sync.cpp` | `Installed::chargedBytes`, `InstallFailed`, `Retired`, `TickFacts::claims`; sightings | `ActorRecord::syncState` (claims included), `render` erased on `Retired`, `reinstallLevel`, `returnBytes`, the waiting installs, `World::budget` through `Charged` |
| 2 | `RecordRenderResults` | R1 | `orchestration/Lifecycle.cpp` | every `ActorEvent`, through `OnEvent`; `PlanJobBuilt` and `PlanJobFailed`; sightings | `render` created on `PlanAwaited`, `Installed` or `InstalledWithoutRender`, with its level costs; `InstalledRender::phase`, `renderedFrame`, `ActorRecord::sight` |
| 3 | `RunBudget` | R2 | `orchestration/Budget.cpp` | the memory sample (only when present), each `InstalledRender` | `World::budget`, `World::radius`, `Live` holding and level requests; commands `ReleaseIntermediates`, `Observe`; the pressure, step-down and radius log lines |
| 4 | `RunSync` | R5 | `orchestration/Sync.cpp` | `TickFacts::stale`, `Timers`, frame syncs, `World::budget` through `HeadroomOf` | the sync log, the waiting installs, the timers, `World::budget` through `Released` for a reinstall's replaced bytes; commands `Install`, `Retire`, `Forget`, `Observe`, `KeepModels`, `SettleApplications` |
| 5 | `RunLifecycle` | R1 | `orchestration/Lifecycle.cpp` | each `InstalledRender`, `World::budget` through `AdmitGrowth` | `World::budget` through `Charged` for an admitted step-up, `Live::stepUpBlockedFrom`; commands `SwapResize`, `StartResize`, `AbandonResize`, `ReleaseIntermediates`, `BuildAwaitedRender`, `FailAwaitedRender`, `TickActor`, then one `DrawUnpublished` last |

`Tick` itself is in `orchestration/Tick.cpp`, owned by R1. R3 owns
`tests/orchestration/` except each step's own unit tests, which the step's
stream writes. R7a owns `planners/InstallProgram.*` and does not touch
`src/orchestration/`.

Rules every stream follows:

- A step emits a command only for an actor whose record it may write.
- The engine reports `TickFacts::sightings` keyed by actor for every actor in `World::actors`, and each `StaleActor` carries its own `Sighting`, so an actor the core has not seen yet arrives with one.
- Planners take a 32-bit form id; the core converts with `FormOf` and `ActorOf` (`World.h`) at each planner call, and nowhere else.
- Failure text is called `problem` in every result and command.
- `RunBudget` alone runs pressure, release, step-down, preemption and the radius. `RecordSyncResults`, `RunSync` and `RunLifecycle` change `World::budget` only through the planner functions `Charged`, `Released`, `AdmitGrowth` and `HeadroomOf`.
- `RecordSyncResults` runs before `RecordRenderResults`, so a `Retired` erases the old render before an `Installed` from the same reinstall creates the new one.
- The engine sights every actor in `World::actors`, not only installed ones: the recheck timers and the radius read the distance of evicted and waiting actors.
- The engine reads `World` through a const reference after each tick, for the snapshot, the metrics heartbeat, the census and the regression facts. It never writes `World`.
- The core writes the log lines of decisions (`LogRecord`). An executor writes the log lines of execution, such as `actor … keeps its resolution`.
- A result is an `ActorEvent{actor, RenderEvent}`, an `InstallFailed` or a `Retired`. Install and `BuildAwaitedRender` both report `PlanAwaited`, `Installed` or `InstalledWithoutRender`.
- "Hidden" names only the studio's hidden layers. A render drawn before it is shown is unpublished (`DrawUnpublished`); a release while out of view is `ReleaseReason::kOutOfView`. Trace action names (`hidden_release`, `hidden_stacks`) stay, because the regression tools read them.
- `TickActor` carries the core's decisions as flags (`drawStacks`, `concealSlots`, `hideShells`, `hideLights`, `finishApplications`). The executor applies each flag and decides nothing.
- The core emits the trace records of decisions (`actor_phase`, `actor_phase_ignored`, `first_draw`, `resolution_level`, `budget_step_down`, `budget_radius`, `budget_pressure`). An executor emits the records of execution, because only execution knows the counts (`hidden_release` and `budget_release` steps, `resolution_swap`).
- The engine keeps the tick interval and the memory-sample cadence. The core runs the budget when `TickFacts::memory` is present, and keeps only the recheck timers.
- `BudgetRadius::sinceMs` and `WaitingInstall::sinceMS` are 32-bit. A step converts `TickFacts::now` at that boundary and nowhere else.
- The core estimates an actor's bytes from `InstalledRender::levelCosts` at its applied level and holding, plus the target level's full cost while a resize runs. Today's estimate reads the instances' targets. The two agree when the plan is the same; R3 checks it in a scenario.

## Native tests

- Unit tests per rule.
- A simulator shell that executes commands with counters, configurable draw speed and failure injection: a resize that does not start, a failed plan job, a swap mismatch.
- Scenarios over hundreds of ticks: a crowd arriving at once, an actor that leaves the view during a resize, budget pressure during a burst of first draws, a failed resize, a failed plan job, the radius shrinking and growing.
- Invariants after every tick: no release outside `Live`; an out-of-view swap releases one hold later; at most one resize in flight; the estimate equals the sum of the held costs; a failed level is not asked for again while it stays wanted; each command agrees with its actor's phase.

## Decisions

| Id | Decision |
|---|---|
| R-1 | One pass per tick. A fallible command's result is a fact of the next tick. |
| R-2 | The engine owns resources by actor id, with a per-tick agreement check. The core is not templated over resources. This replaces S3-1 of the ownership plan. |
| R-3 | The core owns the render lifecycle, the budget, install pacing and the sync decision. The engine owns observation and the install and retire executors. |
| R-4 | The core returns trace records. The engine emits them. |
| R-5 | `planners/OutputState.*` and the render phase from ownership stage 3 are building blocks of the core. The phase is concrete in `orchestration/RenderPhase.h`. Stage 3's engine adoption is dropped; it is in `git stash` on `main`. |
| R-6 | The unpublished-draw budget becomes the INI setting `UnpublishedDrawBudgetMs` in R2: default 4, at least 1, at most 16. It reaches the core through `TickSettings` and the engine through `DrawUnpublished::budgetUs`; `MayDrawStack` takes the budget as an argument. |

## Open

- Stages 0 to 2 of the ownership plan (`SlotWrites`, `Hold`, `RetainedStore`, the means and image stores, the failed-resize reset) are on `main`. This branch carries only `planners/Hold.h`, which the render phase needs. How the branch rejoins `main` is not decided.
- A first draw ends after 60 ticks that drew; a resize swaps 60 frames after it began. The two limits measure time differently.
- Waiting installs are checked once per tick, where today they are checked every frame. At the default 60 animation FPS a tick is one frame; at lower FPS an install starts up to one tick later.
- R4 deletes the engine names the core replaces: `PlanAwaited`, `PlanArrival`, `AwaiterStep` and `StepFor` (`engine/PlanJobs.h`); `PlanFailed`, `NoRender` and `ActorRender` (`ManagerApply.cpp`); `InstallLevelChoice` (`engine/ActorBudget.h`); `DrawHidden`, `ReleaseWhileHidden`, `HiddenSince` and `HiddenReleaseDue`. Until then `PlanAwaited` exists in the engine and in `Orchestration`.
