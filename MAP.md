## Flow

These are textual reference counts, not a call graph. Dynamic dispatch,
callbacks, `std::visit` over command variants, and cross-language calls
are invisible, and generic names inflate. Use this to orient, not to
trace.

Reference hubs among C++ identifiers, most referenced first:

- `Check` — 4,585 references over 57 definitions: the test helper `test::Check` in every suite plus the validation verbs (`CheckScalar`, `CheckField`, `CheckLayer`). It says that tests and validation are pervasive, not that one function is hot.
- `recipe` — 3,124. The recipe is still the center of the codebase.
- `Studio` — 2,102: the `Studio::` namespace that the menu layer draws.
- `state`, `actor`, `command`, `session` — 2,022, 1,954, 1,571, 1,446. These are new since the previous map. They are the tick core's vocabulary: actor state, the commands the core issues, and the session queue.
- `vector`, `fields`, `run` — generic names (`std::vector`, field lists, `Run`).

Entry points worth trusting: `SKSEPluginLoad` (the plugin's real entry,
referenced once), `main` in the validator and in each native suite, `Run`
(44 references; the regression run and command runners), `Init` (10) and
`Dispatch` (5). The remaining 2,436 "unreferenced" candidates are noise:
anonymous lambdas (`__anon…`), Python `unittest` classes that discovery
calls by name, and short helpers (`At`, `Of`, `Is`) whose call sites the
textual counter misses.

## Terminology

Generic roots (`const`, `return`, `string`, `size`, `include`, `auto`,
`name`, `uint`, `float`, `optional`, `text`, `view`) are dropped. The
remaining clusters, merged where they name one concept, most central first:

- **recipe** (`Recipe`, `RecipeGraph`, `RecipeRow`, `RecipeKey`, `recipeID`) — the unit of authorship.
- **actor and its tick** (`ActorId`, `LiveActor`, `TrackedActor`, `ActorPlan`, `TickOutput`, `ActorEvent`, `CommandKind`) — the actor core and the tick core: what an actor should show, what it shows, and the commands between the two.
- **render graph** (`RenderPlan`, `RenderPlanKey`, `RenderStepId`, `StepOutputRef`, `RenderValueRef`, `RenderPhase`, `CompositeStackStep`) — how a recipe's outputs become ordered GPU steps, keyed for caching, with a phase per actor.
- **output and layer** (`SurfaceOutput`, `OutputRef`, `OutputRow`) — what a recipe writes, as per-output layer stacks.
- **source, texture and material** (`SourceKind`, `MaterialSource`, `ImageSource`, `NiSourceTexture`, `TextureLab`, `TextureRef`, `TextureSize`) — the data a stack reads and the targets it writes.
- **geometry** (`GeometryId`, `GeometryRow`, `LiveGeometry`, `BSGeometry`) — the mesh a placement binds.
- **field, key and kind** (`FieldKind`, `ScalarField`, `FieldProgram`, `FieldKey`; `RecipeKey`, `FormKey`, `KeyKind`; `SourceKind`, `ResourceKind`) — identity and discriminators. `*Kind` is the tagged-union discriminator and `*Key` the identity record, as before.
- **state** (`MenuState`, `SignalState`, `BudgetState`) — the mutable records, one per owner.
- **event** (`Event`, `EventOrigin`, `EventRecord`, `RenderEvent`) — game events that drive signals, and the render events the engine reports to the core.
- **check** (`CheckScalar`, `CheckField`, `CheckLayer`, `FieldCheckKind`) — validation, per row and per field.
- **studio** (`StudioPage`, `RenderStudio`, `DrawStudioFrame`) — the editor.

Together these state the pipeline the code implements: a **recipe** is
matched to an **actor**'s **geometries**; its **outputs** become **layer**
stacks that read **sources** and **textures**; the **render graph** plans and
draws them; the tick core decides each tick, from **events** and facts,
which commands the engine runs; and the **studio** edits the recipe and
validates it with **checks**.

## Inconsistencies

The analyzers report 8 naming-convention splits, 8 synonym groups and 18
abbreviation pairs. Verification against the source:

- First-party functions are PascalCase except `TextureRef::get`, the validator's `main` and the hook's `thunk`. These follow the smart-pointer idiom, the C entry point and the CommonLibSSE hook pattern; they stay. The C++ "snake_case" functions and namespaces in the counts are anonymous lambdas and namespaces (`__anon…`).
- Member conventions are consistent: camelCase names public record fields and a trailing underscore names private members. The "snake_case" bucket is single-word names (`a`, `above`), which fit both conventions.
- CMake `SCREAMING_SNAKE` cache variables beside `_private` locals, and JSON-Schema keys (`additionalProperties`, `allOf`) beside the recipe format's camelCase and the profile files' snake_case, are deliberate boundaries.
- Synonym groups are leads, not findings: `build`/`create`/`make` (42/21/16), `read`/`get`/`load` (59/29/24), `write`/`set`/`save`/`store`/`put` (56/32/11/7/4), `start`/`run`/`execute` (75/48/25), `find`/`lookup` (52/11), `drop`/`delete`/`remove` (14/6/5), `cancel`/`abort`/`stop` (8/3/2). A shared verb is a finding only when two names do the same thing; checking that needs the shape of each function, which the counts do not show.
- Abbreviation pairs are lopsided toward the full word (`request` 1,385 to `req` 5, `command` 2,240 to `cmd` 1, `error` 1,076 to `err` 2). `dir` outnumbers `directory` 283 to 83; most uses are CMake and Python, where `dir` is the idiom. `str` (633) is mostly `std::string` idioms.
- The dead-code analyzer's 41 candidates are anonymous lambdas, `unittest` classes and an xEdit script, so none is dead. The Windows build reports the real unused code: `SampleOf` (`src/render/TextureLabReadback.cpp`), `PointText` (`src/studio/SourceRows.cpp`), and an unused variable and parameter in `src/menu/ClusterChart.cpp`.
