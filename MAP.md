## Flow

Caveat first, as always: these are textual reference counts, not a call
graph. Dynamic dispatch, callbacks, and cross-language calls are invisible,
and generic names inflate. Use this to orient, not to trace.

Three reference hubs dominate:

- `recipe` — 1,696 references. The recipe record is the codebase's center of gravity; everything reads or edits it.
- `Check` — 1,671 references, but this is a conventional validation-verb (`CheckScalar`, `CheckField`, `CheckLayer`, `CheckOutput`); read it as "validation is pervasive," not as one hot function.
- `Studio` — 1,521 references (`RenderStudio`, `StudioPage`, `DrawStudioFrame`); the UI vocabulary threads through the menu layer.

Entry-point candidates worth trusting: `SKSEPluginLoad` (the plugin's real
entry, referenced once as expected), and conventional names `Run` (22 refs),
`Init` (12), `Dispatch` (5). The remaining ~1,290 "unreferenced" candidates
are noise: anonymous lambdas and short helpers (`At`, `Is`, `Of`, `Ok`,
`Px`) whose call sites the textual counter misses.

## Terminology

The clusters now read as the project's own vocabulary. Generic roots
(`string`, `size`, `value`, `name`, `auto`, `include`, `frame`, `view`)
are dropped. Most central first:

- **recipe** (136 identifiers; the top-weighted cluster) — the unit of configuration: `RecipeRow`, `RecipeKey`, `RecipeEdit`, `RecipeEditor`, `recipeID`.
- **source** (138: `SourceKind`, `MaterialSource`, `MaterialClustersSource`, `ImageSource`) — where a recipe's data comes from.
- **signal** (92: `SignalGraph`, `SignalKind`, `SignalState`, `ConstantSignal`, `ActorValueSignal`) — the evaluated inputs that drive effects.
- **output** (80: `SurfaceOutput`, `LightOutput`, `OutputRow`, `OutputSubject`, `OutputWhere`) and **layer** (82: `LayerSubject`, `LayerOwner`, `SetLayerOpacity`) — what a recipe writes, as per-output layer stacks.
- **mask** (83: `MaskPresets`, `MaskSubject`, `kScratchMask`) — where an output applies.
- **texture** (117: `TextureLab`, `TextureRef`, `TextureScale`) and **material** (97: `MaterialChannel`, `MaterialMap`) — the render-side substrate the outputs land on.
- **actor / slot / geometry** (83 / 56 / 48: `ActorPlan`, `LiveActor`, `BipedSlot`, `SlotPlan`, `SlotWriter`, `SlotContribution`, `GeometryRow`, `LiveGeometry`) — the placement side: which actor, which equipment slot, which mesh.
- **field / key / kind** (77 / 98 / 74: `FieldKind`, `FieldKey`, `FieldBinding`; `RecipeKey`, `FormKey`; `SourceKind`, `SelectorKind`) — the identity-and-discriminator vocabulary; `*Kind` is the standard tagged-union discriminator, `*Key` the standard identity record.
- **row** (75: `RecipeRow`, `OutputRow`, `SignalRow`, `PieceRow`, `GeometryRow`) — the UI's unit of display; tables of rows are how everything is edited.
- **check** (57: `CheckScalar`, `CheckField`, `CheckLayer`) — validation, applied per row and per field.
- **studio / state** (35 / 49: `StudioPage`, `RenderStudio`, `MenuState`, `SignalState`) — the editing UI and its state records.

Together these state the pipeline the code implements: a **recipe** binds
**signals** and **sources** through **masks** into per-**output** **layer**
stacks, placed per **actor** / **slot** / **geometry**, edited as **rows**
in the **studio** and validated by **checks**.

## Inconsistencies

16 findings; most are idiomatic splits, not drift. Python constants in
SCREAMING_SNAKE beside snake_case functions, CMake cache variables beside
`_private` locals, JSON-Schema keys (`additionalProperties`, `allOf`) beside
the recipe format's own camelCase keys (`actorState`, `edgeColor`) — all
intentional boundaries. Anonymous-lambda symbols (`__anon…`) account for
the "lower" buckets in functions and namespaces.

Verification against source resolved the first-party candidates as
follows (fixed 2026-09-20):

- Functions were PascalCase 2,475 to 5. The strays — `endSession`, `invalidateAssignment`, `pickRecipe`, `focusRecipe`, and `remember`, all methods of `ReduceVisitor` in `src/studio/MenuState.cpp` — are renamed to `EndSession`, `InvalidateAssignment`, `SelectRecipe`, `FocusRecipe`, `Remember`. `SelectRecipe` rather than `PickRecipe` because `PickRecipe` is the intent type the same visitor handles, and a member of that name would hide the type in class scope.
- Member conventions were consistent, not a three-way mix: plain camelCase names public record fields and a trailing underscore names private members (212 uses across every module). The only strays were three leading-underscore privates in `src/mesh` (`_parent`, `_size`, `_state`), renamed to `parent_`, `size_`, `state_`.
- The PascalCase enumerators (`CoatNormal`, `ColoredCoat`, …) and members (`DisplacementTexture`, …) all live in `src/cs/BSLightingShaderMaterialPBR.h`, which mirrors Community Shaders' truePBR vocabulary verbatim so it can be compared against upstream. Intentional; left alone.
- `TextureRef::get()` and the hook members `thunk`/`func` keep their lowercase names: the first is the smart-pointer idiom beside `operator->`, the second is the CommonLibSSE hook pattern.

Everything else the analyzer flagged dissolves under the k-constant
convention (`kActorStateCount` reads as camelCase to the classifier) or
the `g_` global prefix (`g_mutex` reads as snake_case).
